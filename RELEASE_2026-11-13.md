# Release 2026-11-13 · v0.4.8

Hardening pass over the Phase 1–4 feature set. One real UI defect found and fixed; verification made repeatable; documentation brought back in step with the product.

## Fixed

### Cash chart overflow at tablet width (P2)
At 768–1024 px the dashboard switches to two columns, leaving the six-month cash chart about 205 px for content that needed 236 px. The chart spilled 31 px outside its panel.

- `.chart-group` gained `min-width:0` so flex items can shrink below their content size.
- `.bar` changed from a fixed `13px` to `flex:1 1 0; max-width:13px; min-width:2px`, so bars shrink on narrow panels and stay at full width where there is room.

### Version drift (P2)
The service-worker cache key had been bumped for Phase 4 (`invoiceflow-v048-phase4-20261112`) while `package.json`, `README.md` and `PRODUCT-DETAILS.md` still read `0.4.0`. Everything is aligned at **0.4.8**.

### Documentation drift (P3)
`README.md` and `PRODUCT-DETAILS.md` described the product as it was on 2026-10-22. They now cover the AI co-pilot, 13-week cash forecast, client intelligence, smart follow-up loop, VAT201 draft and CIPC reminder, and state the real test counts. `DEFECT_REGISTER.md` now marks I-002 and I-003 as fixed and records this pass's findings.

### Dead and dangerous code removed (P2)
`src/lib/validation.js` sat outside `dist/` and was imported only by its own test. Its `validateEmail` duplicated validation already performed by `checkParty` in `dist/core.js` on every save, and its `sanitizeInput` was a naive angle-bracket strip — a function that looks like an XSS defence but is not one.

- Deleted `src/lib/validation.js` and its test.
- Replaced with `tests/ui/input-validation.test.js`, which exercises the real `validateState` → `checkParty` path: malformed emails, over-length emails, valid emails, empty emails and malformed business emails.
- UI coverage went from 3 tests to 5, now against production code rather than a parallel helper.

## Added

### Repeatable browser verification
The visual audit previously lived in a temporary directory and could not be re-run by anyone else. It is now part of the repository:

- `tests/harness/browser-harness.mjs` — zero-dependency W3C WebDriver client that also serves `dist/` itself.
- `tests/harness/ui-audit.mjs` — the audit.
- `npm run test:visual` audits the live site; `npm run test:visual:local` audits `dist/` without touching production.

Coverage: 11 pages × 10 viewport widths (320–1920 px), dark mode, the editor draft guard, the expense-photo dialog, invoice/client/quote detail views, accessibility naming, and offline readiness.

## Known approximations

- The CIPC reminder estimates the annual return at the end of the calendar year; the exact anniversary must be confirmed on the CIPC website. Disclosed in the code and in the compliance panel.
- `src/lib/validation.js` is test-only scaffolding outside `dist/`. Its `sanitizeInput` is a naive angle-bracket strip and must never be used as an XSS defence; production escaping is `esc()` in `dist/app.js`.
