# InvoiceFlow audit · 22 October 2026 · v0.3.1

## Scope and result

Reviewed the application-owned HTML, CSS, JavaScript, service worker, manifest, package scripts, tests and deployment output. This is a static application: business logic and IndexedDB transactions execute in the browser. There is no server API, cloud database, payment gateway, authentication service or AI backend to test. Vendored PDF/font libraries are retained dependencies; this audit is not a forensic audit of their entire upstream implementations or a security certification.

## Findings and fixes

| Finding | Evidence | Change |
|---|---|---|
| Backup restore bypassed invoice issuance rules | New tests failed against the baseline for future-issued dates and blank issued addresses | Restore now enforces those issuance invariants |
| Drafts accepted reversed payment history | Baseline validation accepted an impossible draft payment history | Draft backups reject all payment entries |
| Zero and alternate-padded invoice numbers accepted | Baseline accepted INV-0000 and INV-00001 | Positive, canonical invoice numbers required |
| Malformed business produced internal TypeError | Null business object failed with a property-access error | Useful business-format error |
| Workspace switch could overlap saves/repeated switches | Source assigned mode before awaiting a read; delayed-read coordinator tests exercise the overlap | Keep current workspace until incoming data validates; reject saves/repeated switches while switching; roll back on read failure |
| Workspace could outgrow its own restore limit | Saving had no corresponding 10 MB backup budget; JSON uses multibyte text and pretty formatting | Check the exact formatted UTF-8 backup before committing; reject excessive changes without changing the saved workspace |
| PDF filename used mutable route after awaiting generation | Source read route.id again after awaiting the exporter | Capture an independent invoice snapshot and filename before starting |
| Mobile numeric inputs lacked visible labels | Mobile CSS hid the shared column header | Visible description/quantity/price/total labels; 16px inputs and larger small-button touch targets |
| Dialog title not explicitly associated; short-height sidebar could clip | Source/markup review | Named dialogs, scrollable desktop sidebar, resilient payment text and totals |
| Clipboard rejection had weak manual recovery | Browser clipboard bridge cannot observe the page's clipboard writes | Select message text on rejection and give a manual Copy instruction; successful native clipboard readback remains unverified |

## Automated verification

48 tests pass; all application JavaScript syntax checks pass. Twelve tests were added to the prior 36-test suite. Tests cover invoice arithmetic and transitions, cash dates, reversal history, snapshot immutability, CSV parsing/escaping, backup rejection and roundtrip, exact UTF-8 backup budget, PDF generation/pagination, service-worker offline fallbacks and cache boundaries, workspace-switch interleaving, stale revision rejection, transaction abort preservation and atomic recovery checkpoints.

The transaction/coordinator fault tests execute the actual application coordinator with simulated device reads/transactions and a minimal DOM. They are explicitly simulations, separate from the real browser flows below.

## Production PDF evidence

On the live v0.3.0 production app, captured the actual PDF download event and downloaded file (13,666 bytes). Poppler confirmed one A4 page, PDF 1.7, no embedded JavaScript. Extracted text included INV-0001, Salt & Stone Café, R8,500 invoice total, R0 payments and R8,500 due. Rendered the downloaded page and inspected its typography, table, totals, accented name and footer. The PDF engine is unchanged in v0.3.1; the initiating action now captures its invoice snapshot safely. This closes the earlier production-PDF test timeout as a verification gap; it was not evidence of an application failure.

## Limits and remaining checks

- Actual disconnected browser reload and physical Android/iPad/Safari testing remain unavailable. Service-worker network-failure tests are simulations; production cache readiness was observed previously.
- Native email/share handoff was not sent or completed. Clipboard copy handler resolves, but this automation uses a separate virtual clipboard; readback returned empty, and paste reported no virtual clipboard data. Do not call native clipboard verification a pass.
- Print-dialog PDF output remains distinct from the verified direct PDF exporter.
- No guarantee of universal failure-free operation, independent penetration test, accessibility certification, customer retention or willingness to pay is claimed.
- Vercel deployment protection is retained. Browser access in this session does not establish unrestricted access for every trial user.
